# Code walkthrough

The repository is larger than the code you need to explain. About 350 lines hold the study's ideas, and the rest builds folds, runs experiments, records results and draws figures.

## How one run flows

1. `make_5fold_dataset.py` removes duplicate images and builds the five folds. This ran once.
2. `run_case_5fold_isolated.py` starts one case and gives each fold a fresh process.
3. `pipeline/experiment.py`, in `run_one_fold`, loads the fold, builds the model, trains it and predicts on the test images.
4. `analyze_chapter4.py` turns the saved predictions into tables and paired tests.
5. `generate_gradcam.py` and `gradcam_app.py` explain single predictions afterward.

## The six parts to know

### 1. CBAM: `pipeline/models.py`, lines 69 to 77

CBAM decides what to focus on in two steps:

- **Channel attention (lines 69 to 73):** it pools each feature map to one number by average and by max, passes both through the same small network, and turns the sum into a weight from 0 to 1 per channel. This answers "which features matter?"
- **Spatial attention (lines 74 to 77):** it averages and takes the max across channels, then a 7 × 7 convolution makes a weight from 0 to 1 per location. This answers "where in the image?"

### 2. Proposed model: `pipeline/models.py`, lines 109 to 158

- **Line 111:** takes the last DenseNet201 features.
- **Lines 114 to 131, the diagnosis path:** CBAM, then pooling, Dense 1024, dropout, batch normalization, Dense 128 and the Normal or Subluxation output.
- **Lines 134 to 151, the artifact path:** it branches off before CBAM, so attention cannot remove the evidence of an artifact. Average and max pooling, Dense 256, dropout, then a four-class output.

Both paths share one DenseNet201, which is what makes this multi-task learning. The benchmark is at lines 91 to 106 and uses self-attention on earlier features instead of CBAM.

### 3. Training: `pipeline/models.py`, lines 161 to 228

- **Loss (lines 163 to 166):** diagnosis loss + 0.3 × artifact loss, so diagnosis stays the main job.
- **Stopping (lines 183 to 210):** saves the best model, stops after 5 epochs without improvement, and lowers the learning rate after 3.
- **What it watches (line 220):** the proposed model watches diagnosis loss, and the benchmark watches total loss. This difference is a disclosed limitation.

### 4. Generated artifacts: `pipeline/artifacts.py`, lines 12 to 98

- **Motion blur (line 12):** averages pixels along a horizontal line.
- **Gaussian noise (line 19):** adds random values to each pixel.
- **Metal streak (line 51):** draws one or two bright blurred lines across the image.
- **Choosing one (line 85):** `apply_artifact` applies the artifact selected for that image.

### 5. Preparing a batch: `pipeline/data.py`, lines 181 to 222

For each image: load and resize it, flip and augment it if training, pick and apply an artifact, then scale the pixels. Test artifacts come from a seed based on the file name (line 144), so C2 and C4 see identical test images.

### 6. Grad-CAM: `generate_gradcam.py`, `gradcam` function

1. Run the image and record the feature maps and the class score.
2. Compute how much the score changes with each feature map (the gradients).
3. Average the gradients per map to get that map's importance.
4. Add up the maps using those weights, keep only positive values and scale to 0 to 1.
5. Resize the result over the image as a heatmap.

## Questions the panel may ask

**Why is your code so much longer than the baseline?**
The baseline is one script that trains on one existing split. This study also removes duplicates, builds five folds, runs four cases, generates artifacts, trains a second output and runs paired tests. The model code itself is similar in size.

**Do you have a real artifact dataset?**
No. All artifacts are generated by code and have no clinical confirmation. The 98.50% artifact accuracy shows that the model recognizes these generated changes. It does not show that the model can detect real artifacts in clinical images, and real-artifact testing is future work.

**Is the proposed model better than the benchmark?**
Not shown. C4 has the highest mean accuracy, F1 and recall in V3, but no primary comparison reaches .005. The benchmark has higher precision and specificity.

**Why are there two versions?**
V2 is the primary result. V3 changed the shared training recipe for all four cases, and it is a disclosed second look at the same test folds.

**Is this the exact code that produced the results?**
V3 used this pipeline with `--recipe v3`. V2 used an older single-file trainer, revision `9249331`, whose hash matches the saved V2 records. The current pipeline is a later reorganization of it, and Fold 1 checkpoints of all four V2 cases regenerated their saved predicted classes exactly.

**What does Grad-CAM prove?**
Only where the model's evidence is strongest for a prediction. It is qualitative, has no expert validation in this study, and does not show that the model is medically correct.

**Could the same patient be in training and testing?**
Possibly. Patient IDs are unavailable, so folds separate exact duplicate files and not patients. This is a stated limitation.

**Why does the app ask for a fold?**
Each fold has its own saved model. In Auto mode the app uses the model that never trained on the chosen image, so the result is a fair test.
